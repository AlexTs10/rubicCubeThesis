\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

The Rubik's Cube is one of the most famous combinatorial puzzles, with a state space exceeding $4.3 \times 10^{19}$ distinct configurations. Finding optimal solutions---i.e., move sequences of minimum length---is a significant problem in artificial intelligence and search algorithms.

This diploma thesis addresses the implementation and comparative evaluation of three Rubik's Cube solving algorithms:
\begin{itemize}
    \item \textbf{Thistlethwaite's algorithm} (1981), which uses four successive phases to gradually reduce the search space.
    \item \textbf{Kociemba's algorithm} (1992), which reduces the search to two phases and produces near-optimal solutions in practice.
    \item \textbf{Korf's algorithm} (1997), which provides the optimal-search framework based on IDA* and pattern databases.
\end{itemize}

The work combines a shared cube representation, independently implemented
solver paths, benchmark tooling, validation scripts, and educational interfaces
to study the practical trade-offs between solution quality, runtime, memory
use, and optimality guarantees.

Experimental evaluation confirms that:
\begin{itemize}
    \item Thistlethwaite's corrected pure implementation solves all 100 benchmark scrambles, but with substantially longer solutions than the other two methods.
    \item Kociemba's algorithm achieves 100\% success on the benchmark corpus with average solution length 14.33 moves.
    \item The external exact backend used for the Korf benchmark path solves 97/100 benchmark scrambles within the enforced 120-second limit and returns optimal solutions whenever it completes. This is the exact backend used for the main 100-scramble Chapter~7 benchmark.
    \item The repository-native exact solver is evaluated separately from that external benchmark backend. It is exhaustively validated on 3,501 non-solved states at depths 1--3. On the 3,513-case canonical native-validation corpus, enabling the native corner pattern database support reduces native failures under a 20-second limit from 3 to 1.
    \item In the implemented A*/IDA* baseline comparison, IDA* uses less memory than the included A* implementation, at the cost of repeated node expansions.
\end{itemize}

The implementation includes an extensive test suite with separate fast, slow,
external-backend, and cache-building validation profiles, interactive
applications for demonstration, and educational materials in the form of
Jupyter notebooks.

The source ZIP together with the documented Python, TeX/Tectonic or Docker,
and Node toolchains is sufficient for the default fast tests, thesis build,
checked-in benchmark inspection, and a smaller native-exact smoke validation.
The checked-in PDF remains directly inspectable without these build tools.
Regenerating the full canonical native-validation comparison requires the
generated \texttt{data/pattern\_databases/corner\_db.pkl} companion cache and
the optional \texttt{RubikOptimal} external oracle backend, which are not
embedded in the source ZIP.
